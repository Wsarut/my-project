ข่าวสาร / page integrity

เว็บข่าวโดนเจาะแบบไม่พังทันที มักเริ่มจากคำพูดผิดโทนหรือหน้าแรกเล่าเรื่องแปลก

scanarticlehomepagebaseline

case A: เนื้อหาข่าวผิดปกติ

เริ่มจากหัวข้อหรือย่อหน้าบางจุดเปลี่ยนน้ำเสียง ลองดูบทความหลักก่อนดูหน้าอื่น

scan surface → inspect content → contain article → verify editorial-baseline → confirm stable → restore clean

case B: หน้าแรกถูกเปลี่ยนเนื้อหา

ถ้า hero, ข่าวด่วน, หรือการ์ดข่าวหลายจุดเปลี่ยนพร้อมกัน ให้คิดถึง homepage modules

scan surface → inspect homepage → contain homepage → verify publish-cache → confirm stable → restore clean

อย่ารีเซ็ตทันที ก่อนรู้ว่าหน้าไหนถูกเปลี่ยน ตรวจหน้าแรกก่อน แล้วค่อยไล่หมวดข่าว

ร้านค้า / data gate

ร้านค้ามักไม่พังหน้าตา แต่รั่วที่ข้อมูลลูกค้า ลำดับคำสั่งซื้อ หรือราคาที่ไม่ผ่านฝั่งระบบ

scandatacheckoutserver-pricerestore

case A: ข้อมูลลูกค้ารั่วไหล

ถ้ามีกล่องข้อมูลหรือ session แปลก ๆ โผล่บนหน้าเว็บ ให้คิดว่าขอบเขต data ถูกเปิดเกินจำเป็น

scan surface → inspect customer → contain data → verify server-price → confirm stable → restore clean

case B: คำสั่งซื้อผิดปกติ

ถ้าราคา ยอดสั่งซื้อ หรือ checkout state ดูข้ามขั้น ให้ล็อกลำดับ checkout ก่อนกู้คืน

scan surface → inspect checkout → verify server-price → contain checkout → confirm stable → restore clean

อย่าเชื่อราคาที่เห็นบนหน้าเว็บอย่างเดียว ราคาในคำสั่งซื้อควรถูกเทียบจากฝั่งข้อมูลอีกชั้น

ตั๋ว / inventory lock

เว็บตั๋วต้องดูว่าจำนวนตั๋วจริงกับแรงซื้อผิดปกติสัมพันธ์กันไหม อย่าแก้เหมือนกันทุกเคส

scaninventorybaselineidentityrestore

case A: ตั๋วขายเกินจำนวน

ถ้าเห็นจำนวนขายมากกว่าจำนวนจริงหรือ badge แปลก ๆ ให้ sync inventory ก่อนเทียบ baseline

scan surface → inspect inventory → sync inventory → verify baseline → confirm stable → restore clean

case B: ตั๋วหมดเร็วผิดปกติ

ถ้ามี queue spike หรือคำขอซื้อถี่เกินมนุษย์ ให้ยกระดับ identity ก่อน sync จำนวนตั๋ว

scan surface → inspect identity → identity step-up → sync inventory → confirm stable → restore clean

ตั๋วหมดไม่ได้แปลว่าคนเยอะเสมอไป ดูความเร็วของคำสั่งซื้อและจำนวนต่อผู้ใช้ด้วย
